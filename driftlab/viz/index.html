Welcome to the driftlab dashboard

driftlab runs agents through jobs whose rules keep changing, and measures how they cope against the world's hidden ground truth. Everything here is read from the run logs: watch agents work live, replay finished runs, compare agents across experiments, and browse the research program. Every panel carries its own explanation under its heading.

Core concepts

World

A job at a fictional company — an intake desk, order-form data entry, an inventory buyer, a developer — with seeded hidden rules that decide what is correct. The agent is never told it is in an experiment; it just works the job.

Agent

Anything that answers text with text: it gets an observation, replies with an action, and hears the outcome. An LLM with a memory strategy, a lookup-table baseline, or an external harness such as Claude Code or Antigravity — all play under the same contract and the same metrics.

Drift

How the world changes. Substantive: the correct behavior changes (a rule flips, demand jumps). Cosmetic: only the wording changes, so reacting is a mistake. Self-caused: the agent's own behavior triggers the change, and nothing external marks the moment.

Experiment

A protocol laid over a world: when drift happens, what memos and probes appear, and what gets measured. There are fifteen, each registered with its hypothesis, variables and a version (see Research). The same experiment can run on any world that supports what it needs.

Regime

One condition within an experiment — for example surface vs latent change, or a drift rate of 0, 4 or 12. Regimes crossed with seeds (the world's random draw) make the grid of cells an experiment runs; the same seeds across agents are what make comparisons paired.

Run

One agent playing one cell for a fixed number of steps: one episode, one entry in the Runs list, one trajectory log. The log records every step next to the hidden ground truth the agent never saw, and it is the source everything else on this dashboard is computed from.

Profile & score

Post-hoc measurements over a run directory: detection and recovery lags, retention, stale-memory rate, calibration, cost — normalized into four 0–1 dimensions whose mean is the driftlab score. The vector is the result; the score is a convenience for ranking.

Hypothesis

A scientific claim that spans experiments (H001–H005), kept in the research log with a status and an evidence table that accumulates across runs — contradictions included. Experiments produce numbers; hypotheses are where they become knowledge.

The tabs

Research · Hypotheses

The lab's claims (H001–H005), each with its human status, the machine-proposed verdict from CI-based validation, and the evidence rows behind it — claim, basis and confidence interval per agent and world.

Research · Experiments

The registry: what each of the fifteen experiments tests — its hypothesis, drift types, version, and the machine-checkable prediction it registers for validation.

Research · Benchmarks

How agents compare: the agent × experiment score matrix (click a cell to jump to those runs), mean score dimensions per agent, and per-experiment panels with the adaptation profile, paired effects and metrics tables. Recomputed whenever an analysis runs; the stamp shows when.

Runs · Activity

The selected run as it happens: what the agent sees, replies and is told; its memory, versioned when it writes any; and the world changing — the per-task grid, hidden state and the timeline of changes and memos.

Runs · Performance

Headline tiles (rolling accuracy, cumulative reward, parse failures, world changes, spend, step time) and the reward chart with change markers, recovery shading and stated confidence.

Runs · Configuration

Who played and under what conditions: the agent's recorded profile (pinned, when enforced), the world in plain language, and the experiment's registry definition with the verbatim task text.
