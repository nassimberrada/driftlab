DriftLab System Map

A testbed for how agents cope when the world keeps changing under them. Worlds carry hidden, seeded ground truth; agents just work a job; every claim about learning is measured from the logs, after the fact, with paired statistics. This page is the map of how the pieces fit. The README covers usage; CONTRIBUTING covers additions; the dashboard shows the live state.

The pipeline

Click any box. Data flows left to right and downward: a world and an agent meet in the episode loop, the loop writes logs, and everything else is computed from those logs and nothing else.

Six worlds

Each is a job at a fictional company. The agent is never told it is in an experiment. Three evaluate a choice; three evaluate a result (executed code, a graded form, a numeric decision with consequences). Self-caused mechanisms are off by default so scheduled experiments stay controlled.

Intake desk rule_world

Route each request to one of four desks. A hidden rule table decides which desk is right; tasks repeat, so latencies count in encounters.

Real: a rule flips · Cosmetic: desks relabeled · Self-caused: an overloaded desk sheds work

Order forms form_filler

Copy source records into a structured form, graded field by field, a few attempts per record.

Real: schema mutates · Cosmetic: source columns renamed · Self-caused: IT starts accepting the agent's habitual mistake

Inventory inventory

Order stock against hidden demand; the day's cost combines holding, lost sales and fees. The right answer is a calculation, not a pick.

Real: demand jumps · Cosmetic: report reworded · Self-caused: a big order strains the supplier

Codebase codebase

Implement tickets in Python. Submissions run in a sandbox against tests and are judged against a style guide the agent can never read.

Real: the guide is revised · Cosmetic: ticket template reworded · Self-caused: the reviewer copies the agent's habits

Claims desk claims_desk

Approve or reject narrated insurance claims. A fraud ring runs a signature of attribute values; tracking it as it moves is the whole game.

Real: the signature moves · Cosmetic: template reworded · Adversarial: the ring mimics whatever gets approved
directed drift

Campaign desk campaign_desk

Pick a daily outreach angle. No push is ever scored individually; only a pooled report arrives every period, so credit assignment needs memory.

Real: audience rates redrawn · Cosmetic: angles reworded · Self-caused: a repeated angle wears out
pooled feedback

Nineteen experiments

Eight hypotheses

Hypotheses state claims; experiments ask the questions that test them. Verdicts are proposals computed from the runs, always scoped to the agents and worlds tested; the live board is on the dashboard's Research tab.

H001 memory-shapes-adaptation

How an agent stores what it learns matters more for coping with change than which model it is, and every memory design trades speed of noticing against durability of knowledge.

H002 surface-overreaction

Agents over-react to how things look and under-react to how they work.

H003 self-caused-drift

The changes an agent causes itself are the ones it is worst at seeing: no memo announces them.

H004 environment-engineering

You can make an agent learn faster without touching the agent: task order, feedback richness and timing, and change pacing are all environment-side dials.

H005 calibration-tracks-drift

An agent's stated confidence sags when the world shifts, before its behavior recovers, making confidence a cheap change detector. Blocked until a confidence-lag metric exists.

H006 update-on-dynamics

Agents update on the size of a surprise, not on how their world actually changes, so they abandon correct behavior when feedback merely lies and cling to stale behavior when rules really move.

H007 consolidation-pays-at-context-death

Notes and transcripts tie while raw history persists; consolidation earns its cost only when the context is severed.

H008 adversarial-chase

Against an adversary that adapts to you, adaptation never settles: becoming confident is what triggers the next shift.

Agents and routes

In-process, over an API

A model plus a memory substrate: none, transcript, notes, skills, beliefs, or fastslow. Substrates are the arms of the memory experiments; any transcript or notes can be wiped mid-run. Calls are priced, budgeted and cached; OpenRouter slugs route automatically.

A harness, two ways

Path A, autonomous: the harness plays through the MCP server at its own pace with an optional versioned notebook; the launcher pins its model so the header carries enforced facts. Path B, controlled: the CLI is called once per step and slots into the normal grid with paired seeds and its own reported costs. Where A and B disagree is itself a finding.

The roster lives in agents.json: model-first names (g56luna_codex, sonnet5_api_low_notes), one name per configuration, because the name is what runs are grouped, resumed and compared by.

Run modes

fullthe real thing: 90 to 160 step episodes, 5+ seeds. --quickhalf-length episodes and a smaller task space where the world supports it; stays above the 30-step validity floor and counts toward profiles and verdicts. Confirm anything that matters at full length. --smokea tenth of everything, one seed: a plumbing check that never counts. With --mock it needs no credentials.

Mechanically: experiments wrap step counts in q(), which the active mode scales; COMPACT_WORLDS shrinks a world's task space in reduced modes (fewer request types, fewer claim categories) so each task is still revisited often enough for encounter-based latencies; and the mode is stamped into every run's config, which is how smoke runs are excluded downstream while quick runs count.
