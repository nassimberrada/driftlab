One loop, measured against hidden truth

driftlab is a controlled laboratory for studying how agents form, update, retain, invalidate, and act on knowledge while the world keeps changing. An agent is anything that answers text with text. It gets a job at a fictional company, and the rules of that job change: on a schedule, cosmetically, or in reaction to what the agent does. Every step is logged next to the world's hidden ground truth, so learning is measured against reality rather than a benchmark score, and the same metrics apply to an in-process LLM loop, a lookup table, or Claude Code playing over MCP.

Four jobs at fictional companies

Every world is a plain job. The agent is never told it is in an experiment: episode transitions read as reassignment to a different site, notices read as office memos, and evaluation probes as a supervisor's quick check. Each world can change substantively (the correct behavior changes), cosmetically (only the wording changes), or endogenously (the agent's own behavior triggers the change).

Capabilities

Experiments declare what they need; worlds declare what they have (driftlab/worlds/base.py). A world missing a needed capability refuses the experiment at startup.

The experiment registry

Every experiment has a machine-readable definition in experiments/registry.py: hypothesis, variables, drift types, version. The definition is stamped into every run's manifest, and versions bump instead of experiments mutating, so old results stay interpretable. Click a row for the full entry.

Research hypotheses

Claims rather than experiments: one file each in research/hypotheses/, with a status and an evidence table that accumulates across experiments, contradictions included.

Every way to run driftlab

All commands run from the repo root; uv run auto-syncs the environment. Add --quick to anything for a tenth-length run. Quick mode checks the setup, and its numbers are noise; don't draw conclusions from it.
